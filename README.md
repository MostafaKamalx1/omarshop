# MobileShopDB

قاعدة البيانات دي معمولة لـ MongoDB، وبتنشئ أربع collections:

- `products`
- `customers`
- `invoices`
- `payments`

## التشغيل

1. تأكد أن MongoDB شغال وأن أمر `mongosh` متاح.
2. من داخل مجلد المشروع شغّل:

```bash
mongosh "mongodb://127.0.0.1:27017" mongodb/init.js
```

السكربت ينشئ قاعدة `MobileShopDB`، ويتأكد من أنواع وقيم البيانات، ويضيف indexes للبحث والعلاقات. السكربت آمن لإعادة التشغيل ولا يحذف collections أو بيانات موجودة.

## تشغيل التطبيق بالكامل

1. انسخ `.env.example` إلى `.env` وعدّل `MONGODB_URI` إذا كان MongoDB على عنوان مختلف.
2. شغّل MongoDB محليًا، أو باستخدام Docker:

```bash
docker compose up -d mongodb
```

ثم تأكد من الحالة:

```bash
docker compose ps
```

3. لتشغيل الواجهة والـ API معًا استخدم:

```bash
npm run dev:all
```

أو شغّل كل جزء في نافذة مستقلة، الـ API أولًا:

```bash
npm run server
```

وفي نافذة ثانية شغّل الواجهة:

```bash
npm run dev
```

للنشر على رابط عام مثل `https://promise-hasty-frog.abasthan.app` استخدم:

```bash
npm install
npm run build
npm start
```

ويجب أن تضبط منصة النشر متغير `MONGODB_URI` على رابط MongoDB سحابي، وأن تستخدم قيمة `PORT` التي توفرها المنصة. الخادم يخدم الواجهة من مجلد `dist` والـ API من نفس الدومين تحت `/api`.

في Railway يمكن استخدام أي من أسماء متغيرات MongoDB التالية إذا كانت الخدمة أنشأتها تلقائيًا: `MONGODB_URI` أو `MONGO_URL` أو `MONGO_PRIVATE_URL` أو `MONGO_PUBLIC_URL`.

### نشر مجاني على Render

يوجد ملف `render.yaml` جاهز للنشر على Render باستخدام MongoDB Atlas:

1. أنشئ قاعدة بيانات مجانية على MongoDB Atlas وخذ رابط الاتصال باسم قاعدة البيانات `MobileShopDB`.
2. ارفع المشروع إلى مستودع GitHub خاص أو عام.
3. في Render اختر **New > Blueprint** واربط مستودع GitHub، وسيقرأ ملف `render.yaml` تلقائيًا.
4. عند طلب `MONGODB_URI` ضع رابط MongoDB Atlas، ثم نفّذ النشر.
5. من Settings ثم غيّر اسم الخدمة إلى `omar-shop` إن كان متاحًا. الرابط المتوقع:

```text
https://omar-shop.onrender.com
```

Render يفعّل HTTPS تلقائيًا. الخطة المجانية قد توقف الخدمة بعد فترة من عدم الاستخدام، ثم تعيد تشغيلها عند فتح الرابط.

### النشر على Railway باستخدام HTTPS

1. أنشئ مشروعًا جديدًا في Railway وارفع مجلد المشروع أو اربطه بمستودع GitHub.
2. أضف متغير البيئة:

```env
MONGODB_URI=mongodb+srv://username:password@cluster.mongodb.net/MobileShopDB
```

3. استخدم ملف `railway.toml` الموجود في جذر المشروع. سيستخدم Railway تلقائيًا:

```text
Build: npm run build
Start: npm start
Health check: /api/health
```

4. من Settings ثم Networking اختر **Generate Domain**. سيصدر Railway رابطًا يبدأ بـ `https://`، ويمكن فتحه من أي جهاز أو تثبيته على الهاتف.

### HTTPS داخل شبكة Wi-Fi

تم تجهيز شهادة محلية للتجربة داخل الشبكة. شغّل النسخة الآمنة مباشرة:

```bash
npm run build
npm run start:https
```

الأمر يقرأ الشهادة الجاهزة تلقائيًا من `certs/omar-shop-local.pfx` ويشغّل التطبيق على المنفذ `8443`. إذا نقلت الشهادة لمكان آخر، استخدم `HTTPS_PFX_PATH` و`HTTPS_PFX_PASSPHRASE`.

ثم افتحه من أي جهاز على نفس الشبكة:

```text
https://192.168.1.12:8443/
```

هذه شهادة محلية، لذلك سيظهر تحذير أمان أول مرة. يمكن تنزيل الشهادة من زر **تحميل شهادة HTTPS** داخل الإعدادات، أو استخدام الملف `certs/omar-shop-local.cer` مباشرة. الشهادة المحلية ليست مناسبة للنشر العام على الإنترنت.

للتطوير فقط، يعمل الـ API على المنفذ `4000` وواجهة Vite على `5173` (أو المنفذ التالي إذا كان مشغولًا)، مع تمرير `/api` تلقائيًا للـ API. أما الاستخدام من الهاتف فالأفضل فتح نسخة HTTPS الموحدة:

```text
https://192.168.1.12:8443
```

للحصول على عنوان IP في ويندوز شغّل `ipconfig` وابحث عن `IPv4 Address`. اسمح لـ Node.js أو للمنفذين `4000` و`5173` من Windows Firewall عند ظهور رسالة السماح. لو MongoDB غير شغال ستظهر الواجهة بدون بيانات ولن تحفظ العمليات. للوصول من خارج شبكة المنزل، انشر الواجهة والـ API على استضافة أو VPN بدل فتح المنافذ مباشرة على الإنترنت.

## الوظائف المتاحة

- المنتجات: إضافة، بحث، حذف، متابعة المخزون والتنبيهات.
- العملاء: إضافة العملاء ومتابعة الأرصدة.
- الفواتير: بيع أكثر من منتج، خصم المخزون، وحساب المتبقي تلقائيًا.
- المدفوعات: تسجيل دفعة مرتبطة بفاتورة أو على حساب العميل.
- لوحة التحكم: إجماليات المبيعات، الفواتير، الأرصدة، وحالة المخزون.
- الإعدادات والتنبيهات: اسم المتجر وحد التنبيه محفوظان على الجهاز.

## شكل عنصر الفاتورة

كل عنصر داخل `invoices.items` يحتوي على:

```js
{
  productId: ObjectId,
  name: "اسم المنتج وقت البيع",
  quantity: 1,
  unitPrice: 100,
  total: 100
}
```

`invoiceId` في `payments` اختياري، حتى يمكن تسجيل دفعة على حساب العميل بدون ربطها بفاتورة محددة.
